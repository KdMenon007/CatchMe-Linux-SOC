# Linux SSH Journal

## Project

**Project:** CatchMe Linux SOC — Project 01  
**Incident ID:** `CATCHME-LNX-001`  
**Scenario:** SSH Brute Force Detection  
**Target:** `soc-linux` (`192.168.1.16`)  
**Attacker:** Kali (`192.168.1.10`)  
**Target Account:** `socadmin`  
**Service:** SSH (`TCP/22`)

---

# 1. Query Objective

This document describes the supporting Linux command used to validate the Elastic SIEM authentication events against the SSH service logs on the Linux endpoint.

The endpoint-side evidence was used to correlate the SSH authentication failures observed in Elastic with the underlying Linux SSH journal.

---

# 2. Linux SSH Journal Query

```bash
sudo journalctl -u ssh --since "2026-10-01 03:27:00" --until "2026-10-01 03:30:00" --no-pager
---
```

# 3. Query Breakdown

### SSH Service

```text
journalctl -u ssh
```

Retrieves journal entries generated by the SSH service.

### Start Time

```text
--since "2026-10-01 03:27:00"
```

Begins the investigation at the start of the detection-validation attack window on the UTC-based Linux endpoint.

### End Time

```text
--until "2026-10-01 03:30:00"
```

Limits the results to the relevant SSH activity window.

### Output Mode

```text
--no-pager
```

Displays the complete results directly in the terminal.

# 5. Observed Endpoint Evidence

The SSH journal recorded authentication activity associated with:

```text
Source IP      : 192.168.1.10
Target Account : socadmin
Service        : SSH
Process        : sshd
```

The journal contained:

```text
authentication failure
Failed password
Connection closed
PAM authentication failure
```

events associated with the controlled attack.

---

# 6. Time Correlation

The Linux endpoint uses UTC.

The corresponding attack time observed in Elastic/Kali was in IST.

```text
03:27:17 UTC
      =
08:57:17 IST
```

This allowed the endpoint journal entries to be correlated with the Elastic authentication events generated during the same attack.

---

---

# 8. Investigation Result

The journal confirmed repeated failed SSH authentication attempts originating from `192.168.1.10` against the `socadmin` account.

The endpoint evidence was consistent with the Elastic authentication-failure events identified during the Project 01 investigation.

The Linux SSH journal independently confirmed the authentication-failure activity observed in Elastic SIEM.

The endpoint evidence supported the correlation between:

```text

    ↓
SSH Authentication Failures
    ↓

    ↓
Elastic Telemetry
    ↓

    ↓

```

No successful SSH authentication was demonstrated during the Project 01 attack simulation.
